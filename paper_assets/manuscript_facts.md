**Encoding / imputation / scaling (`FrameEncoder`, fit on the training fold):**

- Numeric imputation: training-fold median (all-NaN column in a fold -> 0). Nominal imputation: training-fold mode ('Unknown' if all missing).
- `onehot_scaled` (Logistic Regression, Neural Network): numeric z-scored with training-fold mean and std (ddof=0, std 0 -> 1) after median imputation; nominal one-hot.
- `ordinal` (Decision Tree, Random Forest, GB, XGBoost, AdaBoost, Extra Trees): numeric median-imputed, unscaled; nominal -> integer code of the sorted training categories, unseen -> -1.
- `category` (LightGBM): pandas Categorical with the training categories. `catboost`: string categories passed through `cat_features` (unseen -> training mode).
- Feature sets of other datasets: D1 uses 16 legacy features including the grade-derived `credit_score` (`get_dataset('D1')`); D2 = D3 features. Ablation cells (`D3:ir0:cs*`) drop interest_rate and/or swap the credit score (`repeats._parse`).

**Feature-selection step.** *Legacy conference app (`app.py` `perform_feature_selection`, used by `experiments/baseline_repro.py` for the Table I reproduction and D1 protocol work):* four techniques (ANOVA-F `SelectKBest(f_classif)`, mutual information `SelectKBest(mutual_info_classif)`, random-forest importance, RFE with logistic regression on a 5,000-row sample with seed 42) each rank the features, and the final list is the top `n_features=16` by vote count (`app.py:322-358, 725`). The legacy feature set has 16 columns, so n selected = 16 of 16 and the step only reorders columns (tracker: 'legacy feature selection (no-op reorder)'; column order moves Youden-threshold recall, tracker Phase 1). `mutual_info_classif` is unseeded in `app.py` (it uses numpy's global RNG); `experiments/baseline_repro.py` calls `np.random.seed(42)` before it, and with that seed Table I reproduces exactly (tracker decisions log 2026-10-15). *Journal pipeline (D2/D3, headline):* NOT a mutual-information step. `FrameEncoder` has an optional in-fold ANOVA-F selector (`select_k`, `f_classif`); the default is `select_k=None` (`creditrisk/config.py`: 'None = keep all raw features') and no experiment sets it, so all 16 features are kept and there is no selection seed. No mutual-information selection exists in `creditrisk/`.

**realized_profit and P1** (`creditrisk/data.py`): `realized_profit = P1 = total_pymnt - funded_amnt` (undiscounted). Verified on the full file that total_pymnt = total_rec_prncp + total_rec_int + total_rec_late_fee + recoveries on 100% of Fully Paid / Charged Off rows within $1, so `recoveries` is not added again (tracker Phase 2).

**P2** (`creditrisk/data.py` `profit_p2`): `P2 = (total_pymnt - collection_recovery_fee) * f - funded_amnt`, with `f = (1 - (1+r)^(-T)) / (T * ln(1+r))`, `T = months_to_last_payment / 12` (months between issue_d and last_pymnt_d, or the loan term if last_pymnt_d is missing, clipped at 0), `f = 1` if r = 0 or T ~ 0. Assumption stated in the code: payments arrive uniformly between issue_d and last_pymnt_d, funded_amnt leaves at issue_d; late recoveries may arrive after last_pymnt_d so discounting is slightly optimistic.

**Collection fee:** there is no constant. `collection_recovery_fee` is a per-loan column of the Lending Club file (missing -> 0). Its source is the Lending Club file itself; no external source is recorded.

**Discount convention:** annual rate r (p.a., effective annual compounding through `(1+r)^-T` with T in years), grid {0, 2, 3, 5, 8}%; headline 3% described only as an illustrative hurdle rate, not a cost of funds (tracker Phase 3B pre-registration). P1 (no discounting) is always reported alongside.

**Elkan threshold** (`creditrisk/thresholds.py`): `t = c_fp / (c_fp + c_fn)` on calibrated P(default); flag as default if p >= t, approve if p < t. Costs are data-derived from train+val only (`creditrisk/study.py`, `experiments/profit_d3.py`): `c_fn = -mean(profit | default)`, `c_fp = mean(profit | repaid)` (realized profit under the scenario in force). Values recorded: D2, P1: C_FP $2,319, C_FN $7,263, t = .242 (tracker Phase 2; per repeat in `phase2_profit_costs.csv`: C_FN ~7,271-7,283, C_FP ~2,316-2,325, t ~ .242). D3 per-scenario constants are NOT RECORDED as cost values; the resulting Elkan thresholds (mean over repeats) are in `phase3b_profit_d3.csv` (column `threshold_mean`) and in section 11.

**Expected-profit rule** (`creditrisk/expected_profit.py`): approve iff `(1 - p) * mu_good(x) + p * mu_bad(x) > 0`, p = isotonic-calibrated P(default), mu_good / mu_bad = LightGBM regressors of realized profit fitted on repaid / defaulted training loans (300 trees, lr .05, 31 leaves, min_child_samples 100, subsample .8, colsample .9, `FrameEncoder('category')`, application-time features only).

**ECE** (`creditrisk/calibration.py`): 15 equal-frequency bins (sort by predicted probability, `np.array_split` into 15 chunks), `ECE = sum_b (n_b/n) * |mean(y_b) - mean(p_b)|`. Probabilities clipped to [1e-6, 1 - 1e-6] for Brier/log loss.

**Calibrators** (`creditrisk/calibration.py`): Platt = logistic regression (C=1e6) on logit(clipped score); isotonic = `IsotonicRegression(y_min=0, y_max=1, out_of_bounds='clip')`; both fitted on out-of-fold (OOF) training scores.

**EM prior-shift procedure** (`experiments/drift_fixes.py`): `prior_shift(p, pi_old, pi_new) = a p / (a p + b (1 - p))`, `a = pi_new/pi_old`, `b = (1 - pi_new)/(1 - pi_old)`. Saerens-style EM: start pi = pi_old (calibration-year prevalence), iterate pi <- mean(prior_shift(p_iso, pi_old, pi)) up to 200 iterations or |change| < 1e-7, using unlabeled test scores. The oracle variant uses the true test prevalence (not eligible). Result: H14 rejected, the EM variant diverges (tracker Phase 3C).

**Youden** (`creditrisk/thresholds.py`): `t* = threshold at argmax(TPR - FPR)` over `sklearn.metrics.roc_curve` of (labels, scores); rule: flag default if score >= t*. Always chosen on OOF scores of train+val (after calibration where stated) and evaluated on the untouched test set. 'Tuned' = Youden on OOF. Flatness: width of the threshold interval with J >= J_max - .005 (`youden_flatness`).

## 10. Known data-quality issues

- **Legacy zero-fill bug (conference code under pandas 3.0.2):** `fillna(inplace=True)` on a column is a no-op, so 6,151 NaNs remained on the first 100k rows and were zero-filled; 6,112 of them were `employment_length` (labelled '0') (tracker audit item 10; `experiments/baseline_repro.py`).
- **Missing `loan_status`:** 33 rows in the raw file (above).
- **Dropped by the strict label:** every row not Fully Paid / Charged Off / Default (see counts in section 2), i.e. 915,318 of 2,260,668 labelled rows plus the 33 unlabelled ones.
- **Censoring / survivorship:** 36-month loans 2016 28% unresolved, 2017 60%, 2018 88%; 60-month 2014 17%, 2015 33%, 2016-2018 45-90%; 2007-2008 36-month loans have 35-58% dropped for policy-exception statuses (`phase3a_vintage_audit.csv`, tracker Phase 3A). Hence D3 (mature vintages) is the headline.
- **OOT feature missingness:** features missing in >50% of the training window are dropped: `mortgage_accounts` for T=2013 and 2014 (tracker Phase 3B/5A; 36-month refit n = 29,096 / 72,566 / 172,988).
- **App input validation:** 60 of ~1,060 scanned held-out loans (5.7%) failed validation (missing or out-of-range values), so the parity sample is the first 1,000 valid ones (`metadata.parity_excluded_invalid_inputs` = 60; tracker Phase 5 limitations).
- **External datasets:** German Credit 0 missing cells, no leaks; Taiwan 0 missing cells, 35 exact duplicate rows kept, no leaks (`docs/data_cards/`).
- **Per-feature missing-value counts and out-of-range counts in D3 / the full file:** NOT RECORDED.
